# Аудит и исправления `dota2analyser`

Документ — результат работы по отчёту аудита. Для каждой находки указаны: **что было
не так**, **что сделано**, **чем проверяется** и **статус**.

Обновляется по ходу работ; последняя правка — после коммитов `55a0db4` → `248c42e`
(ветка `arena/4a73525d-dota2analyser`, база `d8857f9`).

---

## Как читать статусы

| Статус | Значение |
| --- | --- |
| ✅ **Исправлено** | Код изменён, поведение закреплено автотестом |
| 🟡 **Исправлено, без автотеста** | Код изменён и проверен вручную/компиляцией; автоматического теста нет (честно помечено) |
| ⚠️ **Частично** | Основной сценарий закрыт, остались оговорки — они перечислены |
| ❌ **Не проверено** | В этой среде проверить невозможно (нет сети/браузера) |

### Про `tools/audit-checks.cjs`

Скрипт писался с нуля (в репозитории его не было, хотя отчёт на него ссылался).
Это **напоминание о принятых решениях**, а не спецификация и не доказательство
корректности: он ищет в исходниках характерные признаки (например, «нормализация
принимает `expectedMatchId`», «воркер проверяет список методов»). Зелёный результат
означает «защита на месте», а не «ошибок нет».

## Что осталось непроверенным (честно)

1. **E2E в браузере.** Ни одного живого прогона: нет браузера (ни бинарника, ни
   кэша Playwright). Страницы, демо, импорт, настройки и прогресс проверены
   типами, юнит-тестами и дымовым рендером в jsdom — это не браузерная проверка.
   Для ручной проверки поднимается dev-сервер (`npm run dev`).
2. **Живые ответы Valve и OpenDota.** Сети нет. Контракты опираются на фикстуры из
   документации и открытых датасетов; если реальный ответ отличается — тесты это не
   поймают.
3. **Гонки (3.4) и Error Boundary (5.1)** закрыты по коду, но не автотестами:
   нужен браузер или управляемые таймеры в интеграционном тесте.
4. **`tools/build-data.py` в боевом режиме** не запускался: скачивание архивов
   требует `codeload.github.com` с закреплёнными коммитами, а контрольные суммы
   (`CHECKSUMS`) не заполнены — при первом реальном запуске скрипт напечатает
   фактические SHA-256 (их и нужно записать в `CHECKSUMS`).
5. **Ручная проверка доступности скринридером.** Добавлены `aria-*`, скрытая таблица
   точек и управление с клавиатуры, но реальный прогон (NVDA/VoiceOver) не делался.
6. **Реальное поведение Cloudflare Worker** в облаке не проверялось — только
   `node tools/check-worker.mjs` с подменённым `fetch`.
7. **Офлайн-сценарий с ленивыми демо.** Чанки демо подгружаются по сети: если
   страница взята из кэша, а чанк — нет, пользователь увидит сообщение
   «Демо-данные не загрузились». Это осознанный компромисс ради уменьшения бандла
   (964 → 635 kB); при необходимости можно вернуть статический импорт.
